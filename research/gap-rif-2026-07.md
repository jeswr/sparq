# RIF axis — the NOT-COMPARABLE verdict, codified

> 🤖 SPARQ agent. [FABLE-5] sq-hmd7l.24 (epic sq-hmd7l). **FIRST-READ / NON-CANONICAL.**
> This record codifies the comparative-benchmarking design record's honest verdict for
> the RIF (Rule Interchange Format) axis and documents what BACKS — rather than
> asserts — the "only maintained open-source RIF consumer" claim. Repo hygiene: it
> contains **no hard-coded performance numbers** and **no hard-coded pass counts** —
> pass-rate claims are backed by RUNNER OUTPUT only (`bench/rif/run.sh`), never by a
> number pasted into markdown.

## Axis

The RIF axis of the comparative-benchmarking epic (sq-hmd7l). sparq's RIF surface is
the opt-in `rif-core` / `rif-xml` feature pair of `crates/sparq-reason`
(`src/rif.rs`: the RIF-Core model + Datalog-safety validation + N3 lowering + closure;
`src/rif_xml.rs`: the W3C RIF/XML presentation-syntax importer with a fail-closed
error taxonomy).

## Verdict: NOT-COMPARABLE — this axis is CONFORMANCE-ONLY

**No runnable open-source RIF peer exists to race**, so a head-to-head performance
table on this axis would be fabricated breadth. The peer survey behind the verdict:

| candidate | why it is NOT a comparable column |
|---|---|
| **fuxi** | dead — Python-2-era RIF/N3 reasoner, unmaintained for over a decade, does not install on a modern box |
| **Apache Jena** | dropped RIF — the `jena-jriform`-era RIF support was removed from the maintained distribution; current Jena consumes its own rule format, not RIF |
| **RIFle** | unmaintained — the reference-style RIF engine has had no releases/activity in years |
| **RDFox** | consumes **datalog**, not RIF — a RIF document is not an input it accepts, so any "comparison" would really benchmark a hand translation (and it is commercial, not open-source) |

Consequences, all deliberate:

- The axis emits a **W3C RIF test-suite pass-rate** (pass / fail / skip counts) and
  **no wall-clock**. Nothing on this axis implies a performance comparison — the
  NOT-COMPARABLE framing is part of the runner's own output header.
- **Perf of RIF-translated rules is a different axis**: RIF-Core lowers to N3 and runs
  on the same forward chainer, so its throughput story is measured on the
  **materialization axis (sq-hmd7l.7)** against the reasoners that ARE runnable
  (EYE / cwm / jen3 — see `research/gap-n3-2026-07.md`), never here.
- The **"only maintained open-source RIF consumer" claim must be BACKED, not
  asserted**: what backs it is (i) the peer survey above (every candidate consumer is
  dead, dropped, unmaintained, or not-a-RIF-consumer) and (ii) a runner that
  demonstrates sparq actually CONSUMES RIF against the actual W3C suite with an
  honest denominator. A consumer claim without a conformance arm would be exactly the
  unbacked breadth this epic forbids.

## The runner (`bench/rif/`, registry id `rif-conformance`)

`bench/rif/run.sh` wraps `crates/sparq-reason/examples/rif_conformance.rs`
(`--features rif-xml` — RIF is opt-in; the default build carries zero RIF code):

- **`--smoke`** — SELF-ASSERTING lane over the **vendored subset** in
  `bench/rif/suite/`: sparq-AUTHORED cases in the W3C archive's directory taxonomy,
  because the real W3C RIF files carry **no redistribution license** (even a subset
  is a prohibited derivative — the license gate documented in
  `scripts/fetch-inference-suites.sh`). Every case's verdict — pinned SKIPs included
  — is asserted exactly against `bench/rif/expected.tsv`; exit 1 on any drift.
- **full mode** — the **full-suite pass-rate** over the FETCHED archive under
  `tests/w3c/rif-core/` (gitignored), with a **per-dialect breakdown** (dialect =
  archive prefix, e.g. `Core`), the **named skip taxonomy** (the denominator's
  honesty: `skip:imports` / `skip:condition-shape` / `skip:unsupported-builtin` /
  `skip:non-core`) and an **itemised fail listing — failures are listed, never
  rounded up** into the pass count. Absent archive ⇒ graceful skip, exit 0.

The oracle is a condensed restatement of the `rif-wg-core` conformance lane
(`crates/sparq-conformance/tests/rif_wg_core_suite.rs` — the authoritative,
RATCHET-carrying copy, whose `RIF_WG_CORE_FLOOR` is the rise-only pass-count gate):
import → validate → closure → conclusion satisfaction, the NET vacuity rule (an
un-importable premise is a SKIP, never a vacuous pass, in either polarity) and the
reject-polarity guard (an unsupported-construct rejection never counts as "correctly
rejected"). At implementation time the two were cross-run against the same fetched
`Core_v1.22` archive and produced **identical tallies and skip taxonomies** — the
parity check for the condensed oracle.

## Honest boundary

- The pass-rate is a **conformance** statement about the supported RIF-Core subset,
  with the skip taxonomy carrying the incompleteness (imports-closure, arity-3+
  positional atoms, unsupported builtins, non-Core dialect constructs). It is not a
  completeness claim.
- **BLD/PRD dialects**: the runner's per-dialect breakdown reports whatever dialect
  archives are fetched; only `Core` is consumed today — a fetched BLD archive would
  honestly surface as skip-dominated, not silently omitted.
- We do NOT claim the SPARQL **RIF entailment regime** (`sparql11/entailment`
  rif01..rif06) — the same named out-of-scope item as the `rif-wg-core` lane.
- "Maintained" in the claim means: the importer/validator/chainer live in-tree,
  gated in CI (the `sparq-reason (rif-xml)` feature legs + the `rif-wg-core` lane),
  with a rise-only pass floor. The claim's peer half is re-checkable at any time by
  re-running the survey above; if a maintained RIF peer appears, this verdict is
  WRONG and the axis graduates to a real comparison.
