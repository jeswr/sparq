> Goal (per @jeswr): replicate the **Deep-Taxonomy / LUBM benchmark template** onto every
> capability surface — an *overview* dashboard row, *regression alerts* (a self-asserting
> deterministic gate), and *competitor comparison* — one surface at a time, **SHACL first**.

This record is the single source of truth for **how** to stamp out a new per-surface suite and
**what** each surface's suite should contain. It is deliberately mechanical: the framework is
already built (LUBM is the cleanest worked example); the per-surface work is mostly config +
scripts plus one small per-surface runner, with two genuinely new pieces of shared infra
(external-engine adapters; an approximate/recall gate variant) called out explicitly.

Tasks discovered here are captured as **beads** (`bd`), not as TODOs in this file (repo hygiene
policy). The bead ids are recorded at the end.

## 1. The reusable RECIPE — codified Deep-Taxonomy/LUBM template

To add a per-surface suite `<suite>` (e.g. `shacl`), do all **seven** of these. A suite is only
"done" — overview + alerts + competitor — when it has all seven.

### 1.1 Suite dir + deterministic corpus generator — `bench/<suite>/`

Mirror [`bench/lubm/`](../bench/lubm/):

- **`gen.sh <scale>`** (or `fetch.sh`): emits a **deterministic** corpus to a cached dir under
  `/tmp/<suite>`, prints the corpus path(s) to stdout, sha256-pins any fetched/built tool, exits
  non-zero on failure. LUBM's `gen.sh` emits **two** lines (data ABox + ontology TBox) — SHACL
  similarly needs two artifacts (data graph + shapes graph), so the two-line convention transfers.
- **inputs dir** — `queries/` of `*.rq` for query suites; for SHACL, **shapes files** `shapes/*.ttl`.
  (This is generalization gap **G2** below.)
- **`expected.tsv`** (LUBM calls it `expected-rows.tsv`): the **deterministic golden counts**, one
  per workload. For SHACL: `<workload>\t<conforms>\t<violations>\t<focus_nodes>`.
- **`run.sh`** — the **self-asserting entry point** (the load-bearing piece). The LUBM pattern
  (verified, `bench/lubm/run.sh`): ensure corpus → run the engine in count mode → **assert every
  count vs `expected.tsv`, `exit 1` on any mismatch** → print `<name>\t<count>\t<min_us>` TSV on
  stdout. For SHACL the analog is *validate data×shapes → assert violation-count/conforms ==
  expected, exit 1 on drift*. **The hard correctness gate lives here**, so the timing metrics the
  hook later harvests stay advisory.
- **`README.md`** — workloads, scale tiers (per-commit small vs `*-heavy/` EC2), pinning, cited
  datasets, competitor refs. **No hard-coded perf numbers** (AGENTS.md).

### 1.2 Guarded `ci-bench` hook — `scripts/ci-bench.sh`

Paste-adapt the LUBM block (`scripts/ci-bench.sh`, ~lines 346–371, verified):

```bash
if command -v <required-tool> >/dev/null 2>&1 && [ -x "$<SUITE>_RUN" ]; then
  if CLI="$CLI" ITERS=3 bash "$<SUITE>_RUN" > "$TMP/<suite>.tsv" 2>"$TMP/<suite>.err"; then
    while IFS=$'\t' read -r name count us; do
      [ "${count:-}" = "ERROR" ] && continue
      [ -n "${us:-}" ] && add "<suite>_${name}_<mode>_us" us "$us"   # TREND-ONLY (advisory)
    done < "$TMP/<suite>.tsv"
  else echo "ERROR: <suite> run.sh failed (correctness regression)" >&2; cat "$TMP/<suite>.err" >&2; exit 1; fi
else echo "note: <suite> skipped (<tool> not on PATH)" >&2; fi
```

Invariants (all verified against the LUBM/sp2b/bsbm hooks): **guard on `command -v`** so PRs (which
don't install suite toolchains) skip gracefully and still emit valid JSON; `_us` lines are
**advisory** (never enter `perf-gate.py`); the **hard correctness diff is inside `run.sh`**; the
metric-name convention `<suite>_<input>_<mode>_us` is **load-bearing** (the dashboard + label
generator parse it).

### 1.3 Register a deterministic GATE metric — `bench/perf-baseline.json`

Only for a runner-noise-immune **integer** metric worth cross-commit *ratcheting* (wall-clock is
never gated). Add to `bench/perf-baseline.json` `"metrics"`:

```json
"<suite>_<metric>": { "floor": null, "threshold": 0.02, "mode": "auto" }
```

`mode:"auto"` ⇒ deterministic, hard-gated strictly, auto-ratchets **down** on improvement, never
auto-raises. `floor:null` bootstraps from the first run. The metric must be emitted by the hook's
`add` under that exact name. `perf-gate.py` is data-driven from `mode` (verified) — **no code
change**, just the baseline entry. (Note: `run.sh`'s `exit 1` already gates *correctness* per
commit; a `perf-baseline.json` entry adds cross-commit *ratcheting* of a count — e.g. a closure
size or a violation total.)

### 1.4 Featured dashboard row — `bench/dashboard/dashboard.js`

Add one entry to `FEATURED_SUITES` (verified at line ~196):

```js
{ key: 'SHACL', title: 'SHACL validation', aliases: ['shacl', 'shacl validation'] },
```

`featuredSuiteOf()` token-matches a `shacl_…` metric-name prefix even before labels land. Add the
suite name to `GROUP_ORDER` (line ~145) for stable ordering. The competitor columns + scaling
charts are already generic seams (`competitorsFor()` reading `window.COMPETITORS`) — no other
dashboard change.

### 1.5 Metric labels — `scripts/gen-metric-labels.py`

Add a block in `build()` mirroring the LUBM one (~lines 316–329): a `<SUITE>_DESC` dict +
`for s in stems("<suite>/<inputs>"): labels.update(mode_records("<suite>_"+s, "SHACL", "SHACL
validation", "<dataset desc>", desc))`. Regenerate `metric-labels.json` and commit it (the
`--check` drift gate in `bench.yml` fails CI otherwise). **Caveat G2:** `stems()` globs `*.rq`
only — SHACL inputs are `*.ttl`, so generalize `stems(subdir, ext=".rq")` (small, required).

### 1.6 Registry + catalog — `bench/benchmarks.toml` + `bench/CATALOG.md`

Add a `[[benchmark]]` block (`id`, `category`, `measures`, `invoke`, `source`, `dataset`,
`quiet_box_sensitive`, `pinning`, `records_to`, `status`) and a row to the category table in
`CATALOG.md` + the quickstart. This `[[benchmark]]` `invoke` is also the unit
`bench/ec2-bench.sh launch <id> <sha>` runs verbatim for the heavy tier.

### 1.7 Competitor refs — `bench/competitors.json`

Add an object to `competitors[]` mirroring the EYE entry (verified shape): `id`, `kind`,
`role`, `pinned_version`, `version_source`, `install_recipe`, `run_recipe`, `comparable_suites:
[{sparq_suite:"shacl-validate-bench", note:"same data×shapes; cross-check #violations/conforms
before trusting timing"}]`, `quiet_box_sensitive:true`, `dashboard_engine_id`. The dashboard-seam
keys **`engines`/`values` stay EMPTY in git** (AGENTS.md: no hard-coded perf); a real
`scripts/gather-competitors.sh --run` writes git-ignored
`bench/competitor-results/<engine>-<suite>-<UTC>.json` that a maintainer promotes deliberately.

## 2. Shared-infra GAPS (the genuinely-new work, not template copies)

The recipe above is mechanical. Five things must be **generalized/built** for non-reasoning
surfaces:

- **G1 — Per-surface TSV-emitting runner.** The template assumes the query driver
  `sparq-cli bench <data> <fmt> <queries> <iters> count` → `name\tcount\tus`. SHACL/vector/FTS have
  no such driver. **SHACL** has *no CLI subcommand* (verified: `crates/sparq-cli/src/main.rs`
  dispatch has no `shacl`/`validate` arm — only `query`/`reason`/`bench`/…). Options: add a
  `sparq-cli shacl <data> <fmt> <shapes>` arm, or a `crates/sparq-shacl/examples/bench_shacl.rs`
  (the `coverage-and-benchmark-plan.md` §1.1 choice). Either **must emit the same
  `name\tcount\tus` contract** so the existing hook loop + dashboard naming work unchanged. **This
  is the only blocking engine code for the SHACL suite.** `vectors` has `tests/throughput.rs`-style
  harnesses but no registered TSV-emitting runner; same for `text`/`geo`.
- **G2 — `gen-metric-labels.py stems()` hard-codes `*.rq`.** Non-query inputs (SHACL `*.ttl`
  shapes) need `stems(subdir, ext=".rq")`. Small, required.
- **G3 — External-engine benchmark-runner ADAPTERS (the real gap).** Today
  `gather-competitors.sh` + `competitors.json` carry **three bespoke** integration styles, one
  hand-written `run_recipe` each: Oxigraph (embedded Rust dep, in-process), QLever (Docker HTTP),
  EYE (native binary, file→file). There is **no shared "external engine: pull + run + parse"
  harness**. The new surfaces want **~3 reusable adapter *kinds*** (hang them off `competitors.json`'s
  existing `kind` field; dispatch in `gather-competitors.sh`):
  - **`http-sparql`** — POST query → parse SPARQL-JSON results → count. Shared across **Fuseki**,
    **Virtuoso** (core-SPARQL reference engines from `BENCHMARKS.md`), and the existing QLever HTTP
    path. Does not exist as a reusable unit (QLever's `compare.py` is per-dir).
  - **`report-cli`** — file-in / validation-report-out CLI, **structurally like the EYE adapter**.
    Covers **Jena SHACL** (`shacl validate`), **pySHACL**, TopBraid. Needs a shared
    *validation-report → violation-count* parser (count `sh:result`, read `sh:conforms`) so counts
    are comparable to sparq's `report.results.len()`.
  - **`python-lib`** (or `vector-lib`) — in-process library, cross-language. Covers **FAISS /
    hnswlib / Lucene-via-Anserini**. Closest existing analog is the Oxigraph embedded-dep model but
    cross-language: a small Python harness (build index → query → emit recall@k + latency TSV) plus
    a **recall/correctness oracle** (exact-kNN reference), not a row-count diff.
- **G4 — Approximate gate variant.** The template gate is strict integer equality
  (`expected.tsv`). That maps cleanly to SHACL (violation counts / conforms) and FTS (doc-id sets),
  but **vector ANN is approximate** — no exact golden count. The gate must be **recall@k vs
  exact-kNN**, a *tolerance-banded* comparison the strict-equality `run.sh` doesn't yet support.
  Cross-cutting trick (below): emit recall/nDCG/compliance as **deficits** (`1 - recall`,
  `max_funcs - passed`) so they slot into the smaller-is-better `mode:"auto"` ratchet with zero
  `perf-gate.py` change.
- **G5 — Deep Taxonomy is featured + EYE-compared but not a per-commit hook.** If the owner wants
  the *full* LUBM treatment per surface, DT itself still needs a per-commit deterministic hook
  (closure-size assertion, no EYE) separate from the heavy EYE comparison. ~80% wired today.

**CI-cost discipline (reuse, don't reinvent):** PR tier = lean — `bench.yml` installs suite
toolchains **main-only** (`if: github.ref == 'refs/heads/main'`), so every suite hook's
`command -v` guard skips on PRs ⇒ a new hook adds **zero** PR cost. Per-commit (main) tier =
small + hermetic — cap corpus ~100–250k triples, sub-second queries, heavy cases in `*-heavy/`. Add
a SHA-pinned `actions/cache@<sha>` step keyed on `hashFiles('bench/<suite>/gen.sh')` →
`/tmp/<suite>`. Heavy/competitor tier = EC2/nightly opt-in (`bench/ec2-bench.sh launch <id> <sha>`,
orphan-proof, self-terminating, ~$5/day). **Docker-based competitors (Fuseki/Virtuoso/Jena-SHACL)
can't run on the dev box (no Docker) — inherently gather-only on a Docker EC2 box, exactly like
QLever today; they add zero recurring CI cost (nightly + git-ignored results).**

## 3. Per-surface designs

For each: workload/dataset → **DETERMINISTIC gate** (hard) vs **TIMING** (advisory) → competitors
(license / dockerizable / publishable + honest apples-to-oranges caveat) → suite layout.

### 3.1 SHACL — `sparq-shacl` (FIRST + deepest, per the owner)

**(a) Workload / dataset.** Two tiers. **Correctness tier:** the W3C `data-shapes` core suite is
already vendored and ratcheted (**98/98** `sht:Validate`, `crates/sparq-shacl/README.md`) — the
SHACL analogue of `expected-rows.tsv`. **Perf tier:** the **LUBM ABox** as the data substrate
(`bench/lubm/gen.sh`, deterministic `-univ N -seed 0`, sha256-verified, already in-repo) ×
hand-authored shape graphs — *exactly* what Trav-SHACL and Re-SHACL use. Five committed workloads,
each authored with a **known, fixed fraction of invalid focus nodes** so the violation count is a
deterministic constant at the pinned corpus:

1. `cardinality` — `sh:minCount`/`sh:maxCount`/`sh:qualifiedValueShape` over `ub:Department`/
   `ub:Professor` (Trav-SHACL's min/max core; stresses focus-node enumeration + path counting).
2. `datatype_range` — `sh:datatype` + `sh:minInclusive`/`sh:pattern` over literals (XSD lexical).
3. `class_nodekind` — `sh:class` (with `rdfs:subClassOf*` target closure) + `sh:nodeKind`
   (target selection at scale).
4. `node_paths` — `sh:node` + sequence/inverse/`oneOrMore` paths (inter-shape, Trav-SHACL's hard
   case; recursive path walks).
5. `sparql_constraint` — a `sh:sparql` (§5.2) constraint routing through `sparq-engine` — the path
   unique to sparq's architecture; kept as a separate workload, **not** the headline.

Scale tiers: `univ=1` (per-commit, ~100k triples), `univ=5`/`univ=10` (EC2/heavy).

**(b) Deterministic gate vs timing.**
- **DETERMINISTIC (hard, in `run.sh`, optionally `mode:"auto"` ratchet):**
  `shacl_<workload>_violations` (= `report.results.len()`, the primary gate — Schaffenrath's "count
  of total violations"); `shacl_<workload>_conforms` (`report.conforms`, 0/1 — a correctness drift
  detector); `shacl_<workload>_focus_nodes` (number of focus nodes targets select — a
  target-selection regression detector). Plus a `shacl_w3c_pass` ratchet (98 → only tightens, like
  the conformance ratchets in `ci.yml`). All deterministic at the pinned `(-univ,-seed)` corpus +
  fixed shapes ⇒ `expected.tsv`; `run.sh` exits 1 on any mismatch.
- **TIMING (advisory, `mode:"noise"`/trend-only):** `shacl_<workload>_validate_us` (headline),
  `shacl_<workload>_load_us` (data-graph parse+build), optionally `shacl_<workload>_shapes_parse_us`
  (amortisable via `ShapesModel::parse`). Throughput `focus_nodes/validate_us` derivable for the
  dashboard; never gated.

**(c) Competitors.** This is the **cleanest competitor surface** — all run the *identical*
(data graph, shape graph) pair and emit a `sh:ValidationReport` with `sh:conforms`, so
`#violations`/`conforms` cross-check before any timing is trusted.

| Engine | Lang | License → publishable? | Run mode / docker | Role |
|---|---|---|---|---|
| **Apache Jena SHACL** (`shacl validate --shapes --data`) | JVM | **Apache-2.0 → yes** | first-party CLI; `stain/jena` docker | **Tier-1: correctness oracle + mainstream baseline** (the SHACL analogue of Fuseki). Add first. |
| **pySHACL** | Python | **Apache-2.0 → yes** | `pyshacl` CLI; pip/docker | **Tier-1: W3C reference impl**, easy gather; the "correct-but-slow" anchor. |
| Eclipse RDF4J `ShaclSail` | JVM | EDL/BSD-3 → yes | embedded SAIL + tiny driver | Tier-2: 2nd JVM datapoint; partly redundant with Jena. |
| TopBraid SHACL API | JVM | Apache-2.0 → yes | Jena-based lib/CLI | Tier-2: spec reference impl; close to Jena. |
| Zazuko `shacl-engine` / `rdf-validate-shacl` | JS | MIT → yes | npm | Tier-2 / **WASM-peer** for sparq's browser SHACL story. |
| Corese, dotNetRDF, RDFUnit, maplib, **Trav-SHACL**, Re-SHACL | mixed | mixed OSS | varies | Defer; add Trav-SHACL only if a *traversal-optimised speed bar* is wanted. |

Adapter kind = **`report-cli`** (G3), modeled on EYE. **Honest caveat:** `sparq-shacl` does **not**
dedup results across traversal routes (per its README, matching W3C suite expectations); engines
that *do* dedup will report different `#violations` for the same data ⇒ the cross-check must be
**per-engine expected counts** (or a normalised dedup), not one shared constant. Note this in
`expected.tsv`/README. `sh:sparql` coverage differs across engines — scope perf to constraints all
Tier-1 implement.

**(d) Suite layout.**
```
bench/shacl/
  gen.sh            # reuse bench/lubm/gen.sh for the data graph; emit/copy per-workload shapes
  shapes/<workload>.ttl       # 5 committed shape graphs
  expected.tsv      # <workload>\t<conforms>\t<violations>\t<focus_nodes>  (per-engine note)
  run.sh            # SELF-ASSERTING: validate, assert cols 2–4 vs expected.tsv, exit 1; print
                    #   <workload>\t<conforms>\t<violations>\t<focus_nodes>\t<validate_us>\t<load_us>
  README.md         # workloads, tiers, cited datasets, competitor refs (no perf numbers)
```
Plus: G1 runner (`sparq-cli shacl` arm or `bench_shacl.rs`); `ci-bench.sh` hook (reuse the
`javac`/`rapper` guard since it reuses the LUBM corpus); `FEATURED_SUITES` row; `gen-metric-labels`
block (after G2); `benchmarks.toml`/`CATALOG.md` `shacl-validate-bench` entry; `competitors.json`
Jena-SHACL + pySHACL entries.

### 3.2 Reasoning — `sparq-reason` (already ~80% wired; extend)

**(a) Workloads.** The reasoning estate already has the full LUBM treatment (self-asserting
`run.sh` + `expected-rows.tsv` + featured `LUBM (reasoning)` row + EYE competitor) and
`bench/inference/` (deeptaxonomy gen, EYE head-to-head, `owl-bench.sh`, conformance harness).
`crates/sparq-reason` profiles are **RDFS** + **OWL-RL** + N3 forward closure — **no EL/QL/DL**
(materialization camp; confirmed `research/inference-sota.md`). New workloads to *add* into the
existing seam:
- **A1 — LUBM scaled tiers** `lubm-8`/`lubm-100` (EC2/nightly; per-commit stays LUBM(1)).
  `gen.sh` is already `-univ`-parameterized; generate `expected-rows-univ8/100.tsv` once. Entailed
  counts at fixed `-univ N -seed 0` are scale-deterministic and cross-referenceable to the RR-2023
  VLog/Nemo tiers. **Cheapest high-value add.**
- **A2 — UOBM** (`bench/uobm/`): LUBM's `owl:sameAs`/richer-OWL blind spot. Oxford ISG UOBM
  generator (research-tool — keep gather-only/regenerable, don't vendor; verify license at gather).
  sparq is OWL-RL only ⇒ gate against the **RL-approximation** TBox (UOBM_L), not DL-complete.
- **A3 — `owl:sameAs` equality micro-suite** (`bench/inference/sameas-bench.sh`, per-commit,
  in-script generated, no download): a clique of N mutually-`owl:sameAs` resources × M triples;
  **closure triple count is a closed form of (N,M)** → hard `mode:"auto"` gate, zero external data.
- **A4 — promote DeepTaxonomy to a self-gating suite** (`bench/inference/deeptax/run.sh`): give DT
  the LUBM treatment — hard-assert closure size (dt1k/10k/100k = N+1 entailed) alongside the
  existing advisory timing. Closes gap **G5**. Highest-priority cheap win.
- **A5 — closure-size as a first-class deterministic metric across ALL reasoning suites**:
  `<suite>_closure_triples` (`mode:"auto"`). Byte-deterministic, runner-noise-immune; catches a
  reasoner that silently stops deriving where no query touches. The single most valuable framework
  change for reasoning. (Out of scope: LDBC-SPB; any OWL-DL classification suite.)
- **A6 — OWL2Bench RL profile** (Tier-2, CC-BY-4.0, 22 reasoning queries + RL TBox) for
  profile-coverage breadth; pair with the conformance harness, not the perf dashboard.

**(b) Gate vs timing.** Hard (all `mode:"auto"`): **closure triple-count** (A5, the primary
reasoner gate); **entailed-answer count per query** (LUBM `expected-rows.tsv`); **inconsistency
count** for OWL-RL clash fixtures (`inconsistencies()`). Timing advisory: materialization
wall-clock (`*_count_us`/`_s`); prefer the CLI's engine-internal `in Xs` timer (owl-bench
precedent) over process wall-clock for the trend signal.

**(c) Competitors (beyond EYE).**

|---|---|---|---|---|---|
| **`reasonable` (gtfierro)** | **Rust** | OWL 2 RL materialization | **BSD-3 → yes** | pip / crates.io / static CLI | **ADD FIRST.** The most apples-to-apples competitor possible — a Rust OWL-RL *materializer*: sparq's exact paradigm + profile + language. Embeddable like Oxigraph ⇒ **differential closure-size oracle**. |
| **Nemo (knowsys)** | Rust | Datalog (+existential/neg/agg) | Apache-2.0/MIT → yes | ghcr.io OCI; `nmo` CLI | ADD (Tier-2). Rust datalog SOTA; **no built-in OWL-RL ruleset** (supply RL/RDFS rules once). Best on DeepTax + LUBM-entailed. |

"result SIZES cross-checked" rule. Sequencing: `reasonable` → Jena-rules → Nemo+VLog (shared RL-rule
authoring) → RDFox (deferred behind license).

**(d) Layout.** Clone the LUBM template per A1–A4/A6; reuse the existing inference dir for A3/A4.

### 3.3 Vector / ANN — `sparq-vectors`

**(a) Workload.** The crate **already has the gate** in `tests/`: `recall.rs` (HNSW recall@10
floor 0.95 on 50k×32), `diskann.rs` (Vamana recall@10 floor 0.90), `quant.rs` (PQ/SQ recall),
`throughput.rs` (the `vectors-throughput` registry entry). Promote the `#[ignore]`d recall asserts
into tracked metrics, and add an `ann-benchmarks`-style harness over a real ANN dataset (SIFT1M or
GloVe-100-angular) for a published-comparable recall–QPS curve.

**(b) Gate vs timing.** Hard (`mode:"auto"`): `vectors_hnsw_recall_at10` (floor 0.95),
`vectors_diskann_recall_at10` (0.90), `vectors_pq_recall_at10` — the model ANN deterministic gate
(reproducible at fixed seed vs `nearest_exact` ground truth). **These are larger-is-better → emit
as deficits `1 - recall`** to fit the smaller-is-better `mode:"auto"` ratchet (gap **G4**; the one
adaptation this surface needs, zero `perf-gate.py` change). Advisory: `vectors_hnsw_query_us`,
`vectors_build_s`, QPS.

**(c) Competitors.** The **`ann-benchmarks` harness** reporting **recall–QPS Pareto at matched
recall** (never a single latency number). Kernel peers: **hnswlib** (primary, canonical in-RAM
HNSW), **FAISS** (quantizer/GPU + brute-force ground truth), **ScaNN** (SOTA bar), **DiskANN
reference impl** (oracle for sparq's Vamana `.spqg`). All MIT/Apache/BSD → publishable. Adapter kind
= **`python-lib`** (G3) + exact-kNN oracle (G4). **Loose only:** Qdrant/Milvus/Weaviate (full DBs —
more than sparq; apples-to-oranges in the *opposite* direction from Solr). **No competitor does
ANN-inside-SPARQL over dict-encoded entity ids** — state that surface value is uncontested. This is
the **strongest surface for honest competition** (recall@k is a fair, standard, deterministic
comparator).

**(d) Layout.** `bench/vectors/` harness (or reuse `tests/`); hook runs recall tests `--release`,
harvests recall-deficit floors + advisory QPS; `FEATURED_SUITES` "Vector ANN" row; `competitors.json`
`ann-benchmarks` runner with the matched-recall rule in its note.

### 3.4 Full-text — `sparq-text`

**(a) Workload.** Two axes. **IR-quality (recommended gate):** a small redistributable
**BEIR**/MS-MARCO cut (TREC-COVID or SciFact) with qrels, loaded as RDF literals → **Recall@100 /
nDCG@10** vs qrels. **Latency:** the existing `bench_text` example (1M synthetic 8-word literals,
~10k Zipf vocab; AND/OR/prefix/phrase latency + index B/doc).

**(b) Gate vs timing.** Hard (`mode:"auto"`): **result/hit count** for a fixed query set over the
fixed corpus (`text:matches`/`phrase`/`near` result-size diff — the FTS `expected-rows.tsv`) +
**index bytes-per-doc** (integer-exact, like `store_bytes_per_triple`). With BEIR wired,
**Recall@100 / nDCG@10** become deterministic IR-quality gates (emit as deficits, G4). Advisory:
`text_and_us`/`text_prefix_us`/`text_build_s`.

**(c) Competitors.** **Be honest: Solr/ES are NOT SPARQL competitors** (no RDF/SPARQL; RDF4J
deprecated its Solr backend) — keep them off the dashboard. Two legitimate references: (1)
**Surface peer = Apache Jena Fuseki + `jena-text` (Lucene SAIL)** (Apache-2.0, docker) — same
`text:query`≈`text:matches` shape — the only like-for-like FTS-over-SPARQL comparator. (2)
**Kernel reference = Lucene** (the *embedded library*, not Solr the server — sparq-text is embedded;
a server adds an unfair network layer), via **Anserini** for BM25 on BEIR (Apache-2.0). Scope the
kernel comparison to what sparq implements (token AND/OR, prefix, phrase, proximity/slop,
BM25 k1=1.2/b=0.75) or it's unfair. Adapter: `jena-text` = `report-cli`/`http-sparql`; Lucene =
`python-lib`/JVM (its **own** IR harness/bead, not a SPARQL-suite reuse).

**(d) Layout.** `bench/text/` (synthetic + BEIR loader); hook emits `text_<query>_us` + hit-count
diff + `text_bytes_per_doc` baseline; `FEATURED_SUITES` "Full-Text" row; `competitors.json`
`jena-text` (dashboard) + `lucene-anserini` (labelled "sub-component, not an RDF benchmark").

### 3.5 Geo — `sparq-geo`

**(a) Workload.** The **Geographica** dataset + the **galbiston `geosparql-benchmarking`** Micro
Benchmark (1–2 triple-pattern spatial-function queries) — the standard. Plus the crate's `bench_geo`
example (100k CRS84 points; within/nearest/intersects latency) and a **GeoSPARQL Compliance
Benchmark** (Jovanovik et al.) coverage score.

**(b) Gate vs timing.** Hard (`mode:"auto"`): **result-set size** of each `geof:`/within/nearest
query over a fixed point corpus (the geo `expected-rows.tsv`) + a **compliance-score ratchet**
`geo_compliance_pass` (functions/requirements passing — only tightens, like the W3C ratchets;
emit as deficit `max_funcs - passed`, G4). Floating-point geometry ⇒ gate **counts and pass/fail**,
never coordinate values. Advisory: `geo_within10km_us`, `geo_nearest_k10_us`, `geo_index_build_s`.

**(c) Competitors.** **Compliance bar = GeoSPARQL-Jena / Fuseki-geosparql** (galbiston;
Apache-2.0, docker) — highest compliance, the only triplestore with **full GML + WKT**; since
sparq-geo does both, Jena is the right like-for-like for *coverage*. **Perf peers = Virtuoso,
GraphDB** — but both **WKT-only** (note the asymmetry; GraphDB not fully open). **Loose lower bound
= PostGIS** (relational, no `geof:`/graph joins; the `rstar` R-tree sub-component, **not** a SPARQL
competitor; must match CRS/operation semantics — sparq-geo planar/equirectangular vs PostGIS
geodesic/projected — or it's unfair). Adapter: Jena = `http-sparql`; PostGIS = bespoke/`python-lib`.

**(d) Layout.** `bench/geo/` (Geographica corpus + queries + `expected.tsv`); hook emits
`geo_<query>_us` + result-count diff + `geo_compliance_pass`; `FEATURED_SUITES` "GeoSPARQL" row;
`competitors.json` `geosparql-jena` (dashboard) + `postgis` (labelled non-SPARQL).

### 3.6 RSP-QL streaming — `sparq-rsp`

**(a) Workload.** The existing `throughput` example (1M synthetic sensor readings, 100 sensors,
tumbling/sliding/GROUP-BY, three `EvalMode`s) for perf; **SRBench** queries (real LOD weather
streams) for correctness/expressivity coverage.

**(b) Gate vs timing.** Hard: **per-window result-row count** over a fixed `(triple, ts)` replay
sequence — sparq-rsp is **clock-free, a pure function of the pushed sequence** (its design point),
so its output is fully deterministic and diffable against an expected per-window TSV (the RSP
`expected-rows.tsv`, and a *stronger* gate than any wall-clock RSP benchmark can offer) + the
**three-EvalMode-equivalence** assert (already in tests). Advisory:
`rsp_persistentdict_triples_per_s`.

**(c) Competitors.** The natural peers — **C-SPARQL, CQELS, RSP4J/YASPER** (+ SRBench/CityBench/
LSBench/RSPLab harnesses) — are **service/runtime engines with wall-clock windows**, whereas
sparq-rsp is a deterministic clock-free library. **Any throughput head-to-head is
apples-to-oranges (different time model)** — this is the surface where a competitor *perf* column is
least meaningful. The honest comparison is **correctness/expressivity, not speed**: run the SRBench
query set and assert sparq-rsp produces spec-equivalent windowed results (a correctness oracle, the
EYE role). Mark perf comparison explicitly out-of-scope.

**(d) Layout.** `bench/rsp/` (fixed replay sequence + expected per-window TSV + SRBench queries);
hook emits `rsp_<scenario>_triples_per_s` (advisory) + per-window count diff; `FEATURED_SUITES`
"RSP-QL" row; **no competitor perf column** — optionally an SRBench correctness-oracle entry flagged
"correctness only, time model differs".

### 3.7 HDT — `sparq-hdt`

**(a) Workload.** A fixed `.hdt` archive (vendored `snikmeta.hdt` for correctness; a synthetic
~1M-triple archive via `bench_load` for perf). Compare **load-and-decode-to-native + triple-pattern
resolution** on the *same* archive across decoders.

**(b) Gate vs timing.** Hard (`mode:"auto"`): **triple count** of the loaded graph (the round-trip
already asserts `snikmeta.hdt` → 328 triples — the HDT `expected-rows.tsv`) + the decoded term-set
equality the `roundtrip.rs`/`write_roundtrip.rs` tests enforce. Optionally **bytes-on-disk** of a
`save`-produced archive once the in-memory encoder bead `sq-ashy` lands (until then write goes
through a temp-NT round-trip — encode-perf parity is an explicit non-goal). Advisory: `hdt_load_s`,
`hdt_vs_ntgz_load_s` (a *ratio* — survives box contention per CATALOG).

**(c) Competitors.** **hdt-cpp** + **hdt-java** (rdfhdt reference impls; **core LGPL, tools
Apache**; `rdfhdt/hdt-cpp` docker image exists; tools `rdf2hdt`/`hdt2rdf`/`hdtSearch`). Fair
benchmark = **load time + memory + triple-pattern resolution on the same `.hdt`**, matching mapped
(`mapHDT`/mmap) vs loaded (`loadHDT`/in-RAM) regimes. **Critical honest caveat:** sparq-hdt
**decodes HDT into sparq's own Dict/Graph** (HDT as an *ingest format*) then queries its own
permutation indexes; hdt-cpp/java **query the compressed BitmapTriples in place** (HDT as a
*queryable store*). So **load-and-decode-to-native is the only like-for-like comparison; a
"query over HDT" head-to-head is NOT like-for-like** — gate/compare load+decode only. Adapter =
`report-cli`/docker (behind the `hdt` cargo feature).

**(d) Layout.** `bench/hdt/` (fixed archive + `bench_load`); hook (behind the `hdt` feature) emits
`hdt_load_s` + triple-count diff; `FEATURED_SUITES` "HDT" row; `competitors.json` `hdt-cpp`
(docker digest pin, like QLever).

## 4. Cross-cutting

1. **The one `perf-gate.py` adaptation (G4):** recall/nDCG/compliance are *larger-is-better*; the
   gate is smaller-is-better. Emit them as **deficits** (`1 - recall`, `max_funcs - passed`) so they
   slot into the existing `mode:"auto"` ratchet with **zero code change** (the gate is data-driven
   from `mode`). Keeps the self-asserting deterministic gate property for quality-score surfaces.
2. **Competitor honesty ladder** (meaningful → loose), to bake into each `competitors.json` note:
   **SHACL** (Jena-SHACL/pySHACL — fully like-for-like) > **vector recall@k** (ann-benchmarks
   matched-recall — fair standard kernel) > **reasoning** (`reasonable` — exact-same-paradigm Rust
   OWL-RL) > **geo compliance + Jena** ≈ **HDT load-decode vs hdt-cpp** (fair, but query-over-HDT is
   NOT) > **FTS vs jena-text** > **FTS Lucene kernel** / **geo PostGIS** (loose, sub-component
   only) > **RSP** (perf apples-to-oranges; correctness-only).
3. **Always cross-check result SIZES before trusting any competitor timing** (the registry's
   existing rule): `#violations`/`conforms` (SHACL), `closure_triples` (reasoning), recall@k vs
   exact-kNN (vectors), hit-count (FTS), result-set size (geo), per-window rows (RSP), triple-count
   (HDT).

## 5. Prioritized rollout

Ordered by value × feasibility. Cheap-to-gather (open + docker) vs license-gated noted; per-commit
*small* vs nightly *heavy* CI tiering applies to every suite (recipe §2).

| # | Surface / item | Why here | Competitors (cheap=open+docker / gated) | New infra |
|---|---|---|---|---|
| **1** | **SHACL suite** (the lead) | owner's priority; cleanest competitor surface; data substrate (LUBM) already in-repo | **Jena-SHACL + pySHACL — cheap** (Apache-2.0, docker) | **G1** (`sparq-cli shacl`/`bench_shacl.rs`), **G2** (`stems(ext)`), **G3 `report-cli` adapter** |
| **2** | **Reasoning A4 (DeepTax self-gate) + A5 (`closure_triples`)** | closes G5; highest-value cheap win; no new data/competitor | reuses EYE (have it); `reasonable` cheap (crate) | A5 metric (config-only) |
| **3** | **Reasoning `reasonable` competitor + A1 LUBM scaled tiers** | most apples-to-apples competitor in existence; A1 is `-univ` flip | **`reasonable` — cheap** (BSD-3, crate/pip); A1 EC2-only | embedded-rust-dep adapter (Oxigraph-like) |
| **4** | **Vector ANN suite** | gate already exists in `tests/`; strongest honest-comparison surface | **hnswlib/FAISS/ScaNN/DiskANN — cheap** (MIT/Apache/BSD) | **G3 `python-lib` adapter + G4** recall-deficit gate |
| **5** | **HDT suite** | triple-count gate trivial; fixed archive in-repo | **hdt-cpp — cheap** (docker, LGPL/Apache) | behind `hdt` feature; query-over-HDT NON-goal |
| **6** | **Core-SPARQL Fuseki/Virtuoso (`http-sparql` adapter)** | unblocks SHACL/geo/FTS dashboard columns; the BENCHMARKS.md reference engines | **Fuseki — cheap**; Virtuoso open-source-edition docker | **G3 `http-sparql` adapter** (shared, replaces per-dir QLever compare.py) |
| **7** | **Full-Text suite** | needs a real corpus (BEIR) wired first | **jena-text + Lucene/Anserini — cheap** (Apache-2.0) | BEIR loader; reuse `http-sparql`/`python-lib` |
| **8** | **Geo suite** | needs Geographica corpus + compliance harness | **geosparql-jena — cheap**; PostGIS loose | reuse `http-sparql`; compliance-deficit gate (G4) |
| **9** | **Reasoning Nemo + VLog (RR-2023 set) + UOBM/OWL2Bench** | completes the datalog competitor set; one-time RL-rule authoring | **Nemo/VLog — cheap** (docker, Apache); UOBM gather-only | RL/RDFS rules authoring; UOBM/OWL2Bench gens |
| **10** | **RSP suite (correctness-only) + DeepTax/RDFox deferred** | RSP perf is apples-to-oranges; **RDFox license-gated** | SRBench oracle (open); **RDFox — GATED** (`needs:user`) | per-window TSV gate; RDFox behind license |

**Bottom line:** the per-commit gate + dashboard + label + registry + competitor plumbing is fully
reusable and mechanical (LUBM is the cleanest template). The only genuinely-new infra is (G1) a
TSV-emitting validation/index runner per surface (SHACL has none — needs `sparq-cli shacl` or
`bench_shacl.rs`), (G3) the three shared competitor adapters (`http-sparql`, `report-cli`,
`python-lib`) replacing today's three hand-written recipes, and (G4) a recall-deficit gate variant
for the approximate surfaces. SHACL needs only G1 + G2 + the `report-cli` adapter to ship.
