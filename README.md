A from-scratch **RDF triplestore and SPARQL 1.1/1.2 engine in Rust** — dictionary-encoded
with six sorted permutation indexes, parallel execution, an out-of-core memory-mapped store
with a compressed on-disk format, opt-in RDFS/OWL-RL/N3 inference, a WebAssembly build, and a
W3C-conformant HTTP server. Built to find out how fast a clean, modern RDF engine can be.

> **Status: experimental research engine.** Passes the full W3C SPARQL suites (with four
> documented, spec-justified divergences) and 100% of the W3C SHACL-Core and Update suites. The
> conformance scoreboards are CI ratchets that only ever go up — generated by
> [`sparq-conformance`](crates/sparq-conformance) and published on every run (inference floor
> committed at [`inference-conformance-report.md`](inference-conformance-report.md)). The API is
> unstable and pre-1.0; SERVICE federation is not yet implemented (see
> [`research/roadmap.md`](research/roadmap.md)).

## 🚀 Quickstart

```sh
cargo build --release

# Query a file (Turtle / N-Triples / N-Quads / TriG, optionally .gz / .bz2 / .zst)
cargo run --release -p sparq-cli -- query data.ttl turtle \
  'SELECT ?s ?o WHERE { ?s <http://schema.org/name> ?o } LIMIT 10'

# Build on-disk indexes once, then query them memory-mapped (out-of-core, ~0 heap)
cargo run --release -p sparq-cli -- build data.nt ntriples ./idx
cargo run --release -p sparq-cli -- query-mmap ./idx 'SELECT (COUNT(*) AS ?n) WHERE { ?s ?p ?o }'

# W3C SPARQL Protocol HTTP server on :3030
cargo run --release -p sparq-server -- --addr 127.0.0.1:3030 --format turtle data.ttl
```

As a library:

```rust
use sparq_core::Graph;

let g = Graph::load_str(turtle_text, "turtle")?;
let rows = sparq_engine::query(&g, "SELECT ?s WHERE { ?s a <http://schema.org/Person> }")?;
let json = sparq_engine::query_json(&g, "SELECT (COUNT(*) AS ?n) WHERE { ?s ?p ?o }")?;
```

The CLI, HTTP server, Python (`sparq` on PyPI), and JS/WASM (`@jeswr/sparq`) mirror the same
surface. Per-surface how-tos live in the [usage skills](skills/SKILL.md).

## ✨ Features

The engine **core** is always built; everything else is an opt-in capability crate (none is a
dependency of the core — zero wasm impact, enforced in CI).

- **Store & ingest** — dictionary encoding, six permutation indexes, parallel + streaming
  loaders for the RDF text formats with transparent decompression (`.gz` / `.bz2` / `.zst`),
  delta-overlay incremental updates with an optional write-ahead log, and an out-of-core
  memory-mapped store with optional block-compressed permutations.
- **SPARQL 1.1/1.2 query** — SELECT/ASK/CONSTRUCT/DESCRIBE, the full FILTER built-in set,
  OPTIONAL/UNION/MINUS/VALUES/BIND, aggregation + GROUP BY, ORDER BY, DISTINCT, LIMIT/OFFSET,
  all 8 property-path operators, named graphs (`GRAPH`, FROM / FROM NAMED), sort-merge + hash +
  worst-case-optimal joins, cardinality-based planning, and EXPLAIN / EXPLAIN ANALYZE.
- **SPARQL Update** — the complete operation set over default and named graphs (100% of the
  W3C update suite), incremental and WAL-durable.
- **RDF 1.2 / RDF-star** — quoted triple terms stored structurally; triple-term patterns match
  (including variables inside quoted triples); SPARQL 1.2 builtins and result renderings.
- **Custom functions & dataset views** — register Rust closures under function IRIs
  ([`docs/extension-functions.md`](docs/extension-functions.md)); zero-copy named-graph views.
- **Inference** (`sparq-reason`) — RDFS, OWL-RL, and a Notation3 engine (EYE-validated builtins),
  single-pass materialization, incremental closure maintenance, and opt-in proof trees.
- **Validation** (`sparq-shacl`) — SHACL Core at 100% of the W3C core suite.
- **GenAI toolkit** — schema introspection (`sparq-introspect`), grounded NL→SPARQL
  (`sparq-nlq`), entity-text embeddings + ANN (`sparq-vectors`), structural similarity (`sparq-sim`).
- **More surfaces** — Solid access control (`sparq-solid`), GeoSPARQL (`sparq-geo`), full-text
  search (`sparq-text`), RDF stream processing (`sparq-rsp`), HDT archives (`sparq-hdt`), ZK
  query proofs (`sparq-zk`), and federated MPC (`sparq-mpc`).
- **Interfaces** — a CLI (`sparq-cli`), a W3C SPARQL Protocol HTTP server (`sparq-server`:
  query + update, Graph Store read, streaming, WebSocket subscriptions, Prometheus `/metrics`,
  opt-in time-travel), a WebAssembly build (`sparq-wasm`), and Python / JS packages.

See [`AGENTS.md`](AGENTS.md) for the full crate map and what each one does.
