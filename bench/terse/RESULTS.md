## The question

Does authoring a PKG SPARQL query in the **terse dialect** — lever 1 (`K:<name>`
keywords) and lever 3 (`V("phrase")` concept resolution) — cost fewer cache-discounted
effective input tokens than plain SPARQL, **at no loss of query correctness**? The
metric and the kill-criteria were **pre-registered** (`PREREG.md`) before the run.

## Method (how this was measured / how to reproduce)

1. **Frozen task set** — `tasks/terse_tasks.json`: 30 NL questions over the pinned PKG
   (`crates/sparq-kb/ingest/pkg-instances.ttl`), stratified across 4 strata
   (point-lookup / multi-hop / synthesis / negative). Each task carries a **gold
   canonical SPARQL** whose result rows are the answer-set oracle.
2. **Three arms**, each authoring the SAME question over the SAME PKG:
   - **A — plain SPARQL** (carries the schema card; writes `PREFIX` + prefixed names);
   - **B — terse keyword** (carries `legend_card()`; writes `K:<name>`);
   - **C — terse + `V()`** (as B, plus `V("phrase")` lexical-first resolution).
   The per-arm **reference query** a competent agent writes is frozen in
   `tasks/reference_queries.json`.
3. **Quality** — graded DETERMINISTICALLY and BLIND by the REAL toolchain
   (`grade.py`): the `terse-expand` example (the real transpiler + the silent-rewrite
   canary) and `sparq-cli query` (the real engine). Sub-flags: `parses`, `grounded`
   (no out-of-schema term), `answer_correct` (answer-set **F1** vs the gold query),
   and for arm C `resolution_correctness` (every `V()` bound the **gold** IRI).
4. **Tokens** — cache-discounted effective input tokens
   (`1.0·fresh + 0.1·cache_read + 1.25·cache_write`). **Fidelity here =
   `full-session-transcript`** (sq-bmpzd): a live fan-out spawned ONE fresh Claude Code
   sub-agent per `(task, arm)` — 30 tasks × 2 arms (A, B) = 60 tagged
   `[TERSE task=<id> arm=<A|B>]` runs — each carrying its arm's context card and
   authoring exactly one query. `tokens.py --transcripts <dir>` mined the REAL
   cache-discounted effective input tokens straight from each transcript's
   `message.usage` (the `bench/pkg-dogfood/tokens_real.py` mechanism — no `count_tokens`
   API, no char proxy). These are the tokens the model actually consumed for the whole
   session, not just the authored-query payload the earlier proxy isolated.
5. **Verdict** — `verdict.py` runs the FROZEN pre-registered statistics (paired
   Wilcoxon signed-rank + percentile bootstrap on the A−B / A−C deltas, cache-discount
   survival check) joined with quality, and emits one §5.5 verdict object per lever.

## The honest findings (non-sycophantic — the proxy was WRONG)

1. **The real full-session A/B REVERSES the proxy: lever 1 (`K:`) does NOT save tokens.**
   The earlier input-authoring proxy (#1174) charged each arm only its context card +
   authored-query body, where `K:status` is genuinely ~20% shorter than the `PREFIX`
   line + `pkg:status` — so the proxy reported ≈20% cheaper. **At full-session fidelity
   that vanishes.** Every real sub-agent session costs ~14.1–14.2k effective input
   tokens regardless of arm, because the **fixed session floor** (system prompt + tool
   definitions + the identical task framing) dominates; the ~20% saving on the
   query-body *string* is a few dozen tokens — `0.02%` of the bill the model actually
   pays. The paired median delta is **+3.1 tokens** (B even slightly *more* expensive at
   the median), the split is 18 cheaper / 9 dearer / 3 tied — **noise, not a direction**.
   Wilcoxon `p = 0.13` (not significant), bootstrap CI on the median delta `[0.0, 18.2]`
   **includes 0**. The lever fails **all three** pre-registered token gates. The proxy
   over-estimated the real saving by roughly **1000×**.
2. **Lever 1 still TIES plain SPARQL on quality.** `K:` parses 1.00, grounds 0.97, F1
   1.00 — identical to arm A. So `K:` is not *worse*; it is simply **not a token-saver**.
   It is a **legibility / authoring-fluency** convenience whose token cost is neutral.
   That is the honest framing for any future adoption argument — it must stand on
   ergonomics, **not** on a token claim, because the token claim does not survive real
   measurement.
3. **The negative stratum behaved correctly in both arms** — absent statuses/topics
   returned the empty answer-set (no manufactured rows) in the grade, and the
   live fan-out agents authored the faithful (empty-answer) query rather than inventing
   a value.

## What this means for the K: adoption gate

- **Token verdict: DO-NOT-ADOPT.** At `full-session-transcript` fidelity the `K:` keyword
  layer clears **none** of the frozen token gates (≥20% reduction, p<0.05, CI>0). The
  CONDITIONAL "adopt pending fan-out" from #1174 **did NOT hold up** — the fan-out is the
  arbiter the PREREG named, and it killed the token win.
- **The surface is not *harmful*.** Quality ties exactly. If `K:` is kept, it is on
  authoring-ergonomics grounds (shorter to type/read), with **no token-saving claim**
  attached — the opposite of what the proxy suggested.
- **Lever 3 (`V()`)** was out of scope for this fan-out (this bead is the K: upgrade). Its
  verbatim-prefLabel gap is fixed by `sq-26fdp` (the linker now exact-matches a full
  prefLabel before token overlap, so `resolution_correctness` recovers to 1.0 on the
  frozen set); broad `V()` adoption still rides its own full quality/token A/B.

## Honest caveats (read before citing)

- **Small-N, single-run, but now at REAL full-session fidelity.** N = 30 paired tasks,
  60 real transcripts. The result is robust to grading noise (the gap is ~0.02%, three
  orders of magnitude inside the bar) — there is no plausible noise model under which a
  20% saving was hiding. The earlier ≈20% figure was a **proxy artefact**, now retired.
- **The fan-out measured a controlled query-AUTHORING task** (card + NL question → one
  query, no repo exploration), matching the PREREG "what is measured". A different task
  shape (heavy multi-tool repo work) would only push the dialect difference *further*
  into the noise, not out of it — the session floor only grows.
- **All numbers are work-box / NON-CANONICAL** and regenerated by the harness; they move
  with the PKG snapshot and the session overhead, and are never frozen into a user-facing
  doc.
- **This is the THIRD proxy verdict reversed by real measurement this project** (see
  `bench/EXPERIMENTS.md`: PKG-query and ast-grep/outline were the first two). Re-measure
  work-levers with real tokens before codifying them — intuition and char/byte proxies
  have now misfired three times here, always in the same direction (proxy over-claims the
  token lever).
