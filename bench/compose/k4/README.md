# bench/compose/k4 — the K4 real-model accuracy A/B

Resolves **open question K4** (design `research/fo-llm-bridge.md` §4.3): *does presenting an
answer-row binding as a **label** (`View::UriHidden`) instead of the **raw IRI**
(`View::UriVisible`) change a real model's **answer accuracy** on NL questions whose correct
answer depends on grounding to the right PKG entity?* `compose_ab` (sq-mztg8.1) settled the
model-free half (sound, but ~2.4× larger to read); this settles the **accuracy** half with a
real model, via tagged Claude Code sub-agents (no API key — sub-agent transcripts are the
real-model telemetry, the pkg-dogfood mechanism).

## The pipeline (all deterministic except the model answers/judging)

1. **Generate the frozen battery** — `compose_k4` renders, from the real checked-in PKG, each
   NL question's answer-row bindings under **both** views (via the real `compose` module) plus a
   graph-derived gold answer:
   ```sh
   cargo run -q -p sparq-vectors --features compose --example compose_k4 \
     -- crates/sparq-kb/ingest/pkg-instances.ttl crates/sparq-kb/ingest/agents-findings.ttl \
     > bench/compose/k4/questions.jsonl
   ```
   35 questions × 2 arms = **70 runs**, across 6 question kinds (see below).
2. **Answer (real model, blinded)** — one blinded prompt per (question, arm); the answering
   sub-agent sees ONLY its arm's rows and the NL question (never which arm, never the gold, never
   the word "URI-hiding"). Answers land in `answers_*.json`.
3. **Assemble + judge (real model, blinded)** — `assemble.py` pairs answers to gold and writes
   the **shuffled** blinded judge prompts (the judge sees question + gold + one candidate, never
   the arm). Judge verdicts (1.0 correct / 0.5 partial / 0.0 incorrect) land in `scores_*.json`.
   ```sh
   python3 bench/compose/k4/assemble.py
   ```
4. **Analyze** — `analyze.py` computes per-arm accuracy, the paired delta (HIDDEN − RAW), the
   per-kind breakdown, and an exact two-sided **paired sign test**:
   ```sh
   python3 bench/compose/k4/analyze.py   # -> k4_result.json + k4_pairs.json
   ```

## The 6 question kinds (chosen to span where hiding might help OR be a no-op)

| Kind | Binding(s) | What it probes |
|---|---|---|
| `task-title` | one opaque `kb:task-sq-XXXX` IRI | local name is a meaningless id → **strong-hiding** upper bound |
| `disambiguate-finding` | the full Finding candidate set | pick the one matching a paraphrase; verbatim-text required |
| `punct-concept` | the 3-Concept catalog | the punctuation-heavy `ZK/MPC claim + circuit discipline` label (known failure mode) |
| `about-topic` | one Concept IRI (`topic-…`) | local name is **semi-informative** → the *fair middle* |
| `technique-name` | one Technique IRI (`surface-…`) | local name is **semi-informative** |
| `dep-count` | the `pkg:dependsOn` task set | the answer is a COUNT — **identical info in both arms** → null control |

## Honesty notes

- **Work-box, NON-CANONICAL** (AGENTS.md): real-model answers from this box's sub-agents, not a
  hosted-model benchmark. Directional, single-run, N=35 paired.
- **Blinding** guards arm-leakage on both the answer and judge legs; the `dep-count` null control
  (identical info both arms) calibrates judge bias — it came out **delta 0.0**, as it must.
- The committed `answers_*.json` / `scores_*.json` / `judge_keymap.json` ARE the evidence; the
  per-prompt scratch `.txt` files are regenerated by the steps above and are git-ignored.
